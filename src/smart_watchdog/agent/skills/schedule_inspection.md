# 排稽查

## 何時用
使用者要「排這週的稽查」「先看哪幾家」「幫我挑幾所」「這幾天要查誰」時。

## 畫面對應（本系統是四個頁籤，不是網址路由）
- 派工提案頁籤：`list_institutions` 與 `get_ranking` 都會把畫面帶到這裡。
- 左側是全市地圖。**顏色代表機構類別（公立／非營利／私立），不是風險高低**；
  紅圈才是本批建議查核。被問到顏色就要講清楚這件事。
- 點任一筆會展開它的卷宗；`open_institution` 做的就是這個動作。

## 每個 tool 對畫面做的事
- `list_institutions`：切到派工提案頁籤，套上同一組篩選，並把命中的 id
  標在地圖上。可以說「我把這幾筆標在地圖上了」——本系統有地圖，這句話成立。
- `get_ranking`：同樣切到派工提案頁籤，帶回分層理由 `tier`。
- `open_institution`：展開卷宗。

## 步驟
1. 先確認範圍。使用者沒說行政區就用他負責的行政區，說了就用他說的。
2. `get_ranking` 取現行派工提案（要特定條件時才改用 `list_institutions`），
   預設 20 筆。
3. 逐一說明前三筆為什麼在前面，理由直接引用 `reason` 與 `tier` 欄位，
   **不要自己詮釋**。資料不足的機構仍在名單上，只是排在後面，
   不要說成「未納入名單」。
4. 使用者一開口就是「排」（要一份排程）時，說明完前三筆直接 `export_schedule`
   匯出，不必再等他確認一次——他已經在原本那句話裡要求排稽查了。只是說
   「先看看」「有哪幾家」這種瀏覽性問法時，列完就停，問他要不要匯出。

## 講解節奏
動作前一句說要做什麼，動作後一句說看到什麼，**每句不超過 30 字**。
- 動作前：「我先取現行排序前二十名。」
- 動作後：「取得 18 筆，已列在畫面上。」

不要把動作前、動作後、加一整段清單塞進同一句話。**一句只講一件事。**

**只說明前三筆，不要把整份名單念完。** 名單已經在畫面上了，稽查員自己看得到；
逐筆念二十筆會吃掉整個回合的 token 預算，而且沒有人會聽。要匯出時用
`export_schedule` 的 `towns` 參數，不要把 id 一個一個抄回來。

## 量詞與名次
- 主檔一列是一筆登記，不是一所實體園，一律說「筆」，不說「家」或「所」。
- `priority_rank`（實際交付給稽查員的順序）才是講給人聽的順序。
- `tier` 要翻成中文再講，不要念代碼。

## 缺值與誠實
`items` 是空陣列時照實說「查無符合條件的機構」，不要說「還在載入」或不提。
篩選排出 0 筆是正常結果，不是錯誤，不用道歉或重試。
