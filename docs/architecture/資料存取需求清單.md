# 資料管道實施藍圖

本系統的即時層設計為可插拔管道。目前兩個管道運作中（新聞 RSS、PTT），
其餘三個的介接契約已完成，取得對應憑證後即可接上，
**前端與稽查建議書無須改動**。

下列說明每個管道能取得什麼、需要什麼、以及如何接上。

---



## 一、最高價值：疑似不當對待通報案件（機構層級）

**這是公開資料裡完全不存在、卻是唯一真正的事前預警來源。**

依教育部「處理教保服務機構疑似不當對待幼兒案件注意事項」，流程為
**通報（24 小時內）→ 調查 → 認定 → 處分**。通報早於處分數月。
但通報端（全國不適任教育人員通報查詢系統）需帳號密碼或自然人憑證，
非公開；公開查詢系統只揭露**已裁罰結果**，也就是本系統現有的 1,386 筆。

我們橫向調查了八類、十餘個公開來源（見 `docs/research/05-phase1-results.md`
§20–21），確認公開領域**不存在裁罰前的機構層級訊號**。這不是搜尋不夠徹底，
是制度上沒有開放。

| 需求 | 內容 |
|---|---|
| 資料項 | 案件編號、被通報機構（機構層級）、通報日期、案件類別、處理階段、結案結果 |
| 期間 | 2020 年起 |
| 頻率 | 每月或每週 |
| 去識別 | **不需要**任何個人資訊；不要通報人、被通報人、幼兒姓名 |
| 用途 | 僅作為稽查優先序的輸入，不對外揭露個案 |

**只要這一項到手，系統的預警能力會有質變**：目前唯一經檢定的事前訊號是
官方評鑑（中位提前 268 天），但評鑑是每園約五年一輪的滾動週期；
通報是持續發生的。

## 二、次高價值：1999 與市長信箱的教育局幼教案件（機構層級）

新北市資料開放平台的 1999 資料集只有「民國年月／諮詢／轉接／陳情／總計」
與「機關別」，教育局甚至未單獨列出；市長信箱需案件編號加查詢碼才能檢視。
**公開版本無法歸屬到任何一所園。**

| 需求 | 內容 |
|---|---|
| 資料項 | 案件日期、被陳情機構（機構層級）、案件類別、處理結果 |
| 去識別 | 不需要陳情人任何資訊 |

---

## 三、Google 地圖評論：申請 Maps Platform 金鑰

Places API 提供地點的評分與評論。系統設計為稽查員開啟卷宗時即時取用並顯示。

| 需求 | 內容 |
|---|---|
| 申請 | Google Maps Platform 帳號與 API 金鑰，啟用 Places API (Place Details) |
| 費用 | Place Details 含 `reviews` 落在 **Enterprise + Atmosphere**，每千次 US$25，每月前 1,000 次免費（各級距免費額度獨立）。959 園全掃：當月第一次 US$0，第二次起 US$23.98。一次性解析 1,213 園 place_id 走 Text Search Pro（免費 5,000 次/月），實際 **US$0** |
| 限制 | 每個地點最多回 5 則評論且依相關性排序，**無法建立評論時間序列** |

⚠️ 另須知悉：Google 自 2025-04-30 起移除主要服務 6–18 歲學生之教育機構的
評論功能。比對本市主檔，**279 園（23%）** 的地點實體即為其母校，
這些園在 Google 上不會有可用評論。

## 四、Threads：申請 Meta App Review

| 需求 | 內容 |
|---|---|
| 申請 | Meta 開發者應用程式，權限 `threads_basic` + `threads_keyword_search` |
| 審核 | 未核准前僅能搜尋應用程式自身貼文；核准後可搜尋全平台公開貼文 |
| 建議 | 以教育局名義申請，用途敘明為教保機構監理 |
| 限制 | 每日 2,200 次查詢；官方文件載明對其認定敏感或冒犯之關鍵字**回傳空陣列**（可能涵蓋「虐童」「不當對待」等我們最需要的詞，須核准後實測） |

---

## 五、社群全網覆蓋：循共同供應契約採購輿情監測服務

**PTT 已納入並運作中**——無 robots.txt、無登入、公開搜尋端點。覆蓋確實稀薄
（全板掃描僅對到本市 8 園，主題自 2018 年衰退 95%），但稀薄是這個平台的
真實狀態，不是管道的缺陷：多數園本來就沒有人在討論。它能撈到的是真東西，
例如家長指名某園的反推文。**要擴大社群覆蓋則需採購**，因為
Dcard、Threads 網頁端、Facebook 公開社團
均為登入牆或服務條款所禁，**且 Facebook Groups API 已於 2024-04-22 全面下架**。

台灣公部門的標準做法是採購持有平台授權的輿情監測服務：

| 廠商 | 說明 |
|---|---|
| OpView（意藍資訊） | 已列共同供應契約，為最多政府單位採用，收錄逾 22 萬頻道 |
| QSearch | 目前唯一明確涵蓋 **Threads** 的系統 |
| KEYPO | 另一可比較選項 |

採購時建議於契約載明：**須供應 API 或每日檔案**（而非僅網頁介面）、
須涵蓋 PTT／Dcard／Facebook 公開社團／Threads、
須提供貼文原始連結與發布時間以供人工查證。
