# 財報抽取管線維運手冊

**這份文件回答一件事：明年這個時候，新的一屆財報公布了，要怎麼讓系統跟上。**

> ⚠️ **這條管線做的是「定向抽取」，不是「全頁抽取」。** 目前已讀 2,245 頁／
> 全語料 5,162 頁（**43.5%**），其中 1,672 頁來自依目錄鎖定的六個章節、
> 573 頁來自定向前的全量試跑。**尚有 2,917 頁未讀。**
> 未讀的主要是封面、目錄、會計師查核報告全文與財產目錄——
> 目前沒有任何下游檢核用到它們，但**「沒用到」不等於「沒有內容」**。
> 對外描述時請說「定向抽取」，不要說「全部抽完了」。

[`EXTRACTION_GUIDE.md`](EXTRACTION_GUIDE.md) 講的是「一頁應該怎麼抽才正確」（判讀規則）。
這份講的是「整條管線怎麼重跑、怎麼續跑、怎麼知道它跑對了」（作業程序）。

> 這條管線是**增量**的，不是一次性的。新增一屆財報不需要重跑舊的四屆：
> 抽取以「頁」為單位落檔，已存在且可解析的頁永遠不會被重抽。

## 0. 一分鐘版本

```bash
# 1. 放進新一屆的 PDF
#    data/raw/資料集/非營利園財報/114學年度/N01安溪_114學年度財務報告.pdf ...

# 2. 先讀目錄頁（每份一頁），再據以決定要抽哪些頁
python run.py extract-pages --year 114 --only-page 2
PYTHONPATH=src .venv/Scripts/python scripts/plan_from_toc.py
python run.py extract-pages --pages-from data/runtime/targeted_pages.json

# 3. 重建下游
python run.py nonprofit-panel
python run.py pagewise-facts      # 頁級事實長表，法遵補判的依據
python run.py compliance
python run.py priority
python run.py frontend

# 4. 驗收
python run.py test
```

要讀完整份報告而不只是目標章節，省略 `--pages-from`：
`python run.py extract-pages --year 114`。成本差距約七倍
（全語料 5,162 頁約 7 小時 vs 定向 1,672 頁約 1 小時），
而目前所有下游檢核都只用到定向的那六個章節。

檔名格式必須是 `N<兩位數><園名>_<三位數>學年度財務報告.pdf`——
抽取器用它決定這份報告屬於哪一所園、哪一個學年度，
對不上的檔案會被列出並略過，不會被默默吃掉。

## 1. 這條管線在做什麼

```
data/raw/資料集/非營利園財報/<學年度>/*.pdf        主辦方提供的掃描 PDF
        │
        │  scripts/extract_pages_bedrock.py
        │  ├─ PyMuPDF 逐頁轉 PNG（170dpi）
        │  ├─ Bedrock Sonnet 4.6 視覺抽取（結構化輸出）
        │  └─ 三道護欄（見 §3）
        ▼
data/extracted/nonprofit_pages/<代號>_<園名>_<學年度>/pNN.json    一頁一檔
        │
        │  scripts/build_nonprofit_panel.py
        ▼
data/processed/nonprofit_panel.csv                園 × 學年度的財務面板
data/processed/nonprofit_issues.csv               模型自報的待判讀事項
        │
        │  scripts/run_compliance_checks.py
        ▼
data/processed/compliance_findings.csv            軌 B 的法遵檢核發現
```

每一頁的 JSON 都帶著它自己的產生條件——`model`、`dpi`、`backend`、`identity_ok`、
`schema_problems`——所以半年後看到一個可疑數字，可以直接回答「這是哪個模型、
用什麼解析度、在哪一頁抽出來的」，不必靠記憶。

## 2. 為什麼它可以一直跑下去

### 續跑是設計出來的，不是附帶的

一頁一個檔，而且**「已完成」的判準是「檔案存在**且**解析得開」**，不是「檔案存在」。
被中斷的寫入會留下截斷的檔，若只看存在與否，續跑會永遠跨過那個壞檔
（`scripts/extract_pages_bedrock.py::complete`）。

寫入走 `write_atomic()`：先寫同目錄的 `.tmp`，再 `os.replace`。
同一個檔案系統內的 rename 是原子的，所以讀取者（或下一次續跑）
只會看到「舊狀態」或「完整的新檔」，不會看到寫到一半的。

實務上這代表：**中斷不需要任何善後。** 憑證過期、關筆電、斷網，
下次把同一行指令再打一次就好，已完成的頁一頁都不會重抽。

### 帳本會記下每一次呼叫

`data/runtime/pagewise_ledger.jsonl`，每頁一行，逐次附加：

```json
{"key":"N01_安溪_113/p17","status":"ok","kind":"detail_schedule",
 "in":6248,"out":1060,"identity_ok":true,"problems":[],"ts":1789180273.7}
```

所以即使跑到一半被砍掉，也答得出「跑了多少、花了多少 token、哪幾頁有問題」。
帳本是 append-only 的，多次執行會累積，不會互相覆蓋。

## 3. 三道護欄

抽取的產出會用來決定政府稽查順序。**錯誤的數字比缺漏的數字危險得多**，
因為缺漏看得見，而看似合理的錯誤看不見。所以有三道各自獨立的檢查：

### 護欄一：頁尾代號（防止歸錯機構）

每頁頁尾印有 `<代號>-<頁碼>`。模型必須讀回這個代號，
runner 拿它和「這個 PDF 檔名說的代號」比對：

| 讀到的 | 處置 |
|---|---|
| 相符 | 寫進正式資料 |
| 不符 | 隔離到 `_quarantine/` |
| **讀不到** | **也隔離** |

第三列是重點。讀不到頁尾是**未知**，不是通過——
一頁我們無法確認歸屬的資料，不可以用檔名「推定」的名義進入語料庫。

把數字歸到錯誤的機構是這條管線最嚴重的錯誤，比看錯一個數字嚴重得多，
因為後續每一項法遵發現都會指名錯誤的園。這件事**實際發生過兩次**
（見 [`EXTRACTION_GUIDE.md`](EXTRACTION_GUIDE.md) 步驟零）。

### 護欄二：欄位對齊（防止年度錯置）

結構化輸出保證 JSON 的**形狀**，不保證**語意**。一張表可以是完全合法的 JSON，
同時把兩個數字掛在零個欄位標題底下。

`validate_page()` 檢查唯一一條讓資料可彙整的恆等式——
**每一列的 `values` 長度必須等於該表 `period_labels` 的長度**——
不成立就把該表標記 `aligned: false`，彙整層拒收。

> **這一條是從一個真實缺陷長出來的。** 第一版 schema 給「一頁」一組
> `period_labels`，假設一頁一張表。但 N01 安溪 113 的 p17 上半是
> 112.8.1~113.7.31 的人事費明細，下半是 **113.8.1~114.7.31** 的業務費明細。
> 單一組欄位標題讓下半張表的數字被寫在上半張表的年度底下——**無聲的一年偏移**。
> 模型自己在 `issues` 說了它表達不出來，是容器的問題。
> 現在單位是「表」不是「頁」。回歸測試見 `tests/test_pagewise.py`。

### 護欄三：會計恆等式（防止看錯數字）

彙整時逐園逐年驗算：資產總計＝流動＋非流動、餘絀總額＝累積＋本期、
收入合計＝各科目之和⋯⋯。看錯一個數字幾乎一定會打破其中一條。

```
恆等式：通過 1183 / 失敗 1
⚠ 有恆等式未通過的園-年度（這些數字先不要用）：N15 新月 110（失敗 1 項）
```

運算元缺漏的恆等式一律記為 **skipped 而非 passed**，
所以抽得很稀疏的結果不會靠「沒東西可檢查」拿到高分。

## 4. 實測的成本與時間（2026-09-12，競賽帳號 550561128629）

| 項目 | 實測值 |
|---|---|
| 語料 | 132 份報告／5,162 頁 |
| 本次實際抽取 | **1,672 頁（定向）**，另有定向前試跑 573 頁 |
| 每頁 token | input ~6,248、output ~1,060 |
| 定向耗時 | **64.5 分鐘**（1,672 頁，0.43 頁/秒，並行 16） |
| 若讀完 5,162 頁 | 約 7 小時 |
| 牌價估算 | 定向 US$63.02；全量約 US$179（**見下方警告**） |

### ⚠️ 關於那個金額

`USD_IN_PER_M = 3.00` 是**寫在腳本裡的常數**，US$179 是「token 數 × 公開牌價」
的本地算術，**不是 AWS 帳單**。競賽用的是 Workshop Studio 配發帳號
（`WSParticipantRole`），這類帳號的 Bedrock 費用通常結算到主辦方的付款帳號，
參賽者自己的 Cost Explorer 可能永遠看不到。
**要知道真實成本，去讀 Cost Explorer，不要讀這支腳本的輸出。**

另外 Cost Explorer 本身有**約兩天延遲**：2026-09-12 當天查詢時，
9/11 與 9/12 皆顯示 $0.00，而主控台的「Current month $0.14」
正好等於 9/1–9/10 的每日加總。**當天跑的用量當天看不到，這不代表沒有花費。**

### 加並行、換模型都沒有用（已實測，不要重試）

帳號有 **TPM 上限，約 1,000 tokens/秒**，而且是**帳號層級、不是模型層級**：

| 設定 | token 吞吐 |
|---|---|
| 16 並行，單模型 | 988 tokens/秒 |
| 32 並行，單模型 | 988 tokens/秒 |
| 16+16 並行，**兩個不同模型** | 858 tokens/秒 |

並行從 16 加到 32，吞吐完全沒動，只有延遲從 27 秒漲到 96 秒——
請求在排隊，不是在平行。同時跑兩個模型也沒有突破，證實配額是帳號共用的。

**所以 `--workers` 超過 16 沒有意義**，唯一真正的槓桿是每頁 token 數
（降 dpi 可省約 21%，但必須先做判讀一致性比對再改——
`EXTRACTION_GUIDE.md` 硬性規則 7 記著低解析度判讀產生過看似合理的錯誤數字）。

## 5. 常見狀況

### 憑證過期（最常見）

徵狀：抽取停止，log 出現
`AWS 臨時憑證已過期。到 workshop 頁面重新複製 $Env:AWS_... 四行`。

處置：更新 `.env` 的四個 `AWS_*` 變數，重打同一行指令。
腳本偵測到 `ExpiredToken` 或 `AccessDenied` 會**立即乾淨中止**而不是重試——
這兩種錯誤重試一萬次也不會成功，繼續打只是浪費時間與配額。
（限流與暫時性 5xx 則會退避重試，最多 `--retries` 次。）

### 有頁面被隔離

```
⚠ 3 頁的頁尾代號與檔名不符，已隔離到 data/extracted/nonprofit_pages/_quarantine
```

處置：**人工看那三頁**。兩種可能——PDF 檔名錯了，或那幾頁真的被裝訂到別份報告裡。
兩種都是必須由人決定的事，不要寫程式自動「修正」。

### 有表格對不齊

```
⚠ 12 頁含欄位對不齊的表（已標 aligned=false，彙整時會拒收）
```

這**不是**錯誤，是護欄二正常運作。那些表不會進入特徵，
資料不會被汙染。若同一頁反覆出現，看一下 `schema_problems` 的描述，
多半是版面特殊（跨頁表格、合併儲存格），值得在 prompt 補一條說明。

### 想確認進度而不想等 log

log 每 25 頁才印一行，在 0.1 頁/秒下等於每 4 分鐘動一次，看起來像當掉了。
直接數檔案比較快：

```bash
find data/extracted/nonprofit_pages -name 'p*.json' | wc -l
```

## 6. 什麼還是人工的（刻意的）

- **新一屆 PDF 的取得**：主辦方／教育局發布，沒有公開 API 可自動抓。
- **隔離頁的判讀**：見上。
- **`extract-pages` 不在 `python run.py pipeline` 裡**：
  會花錢、要一小時起跳的步驟不該被順手觸發。它必須是有人決定要跑才跑。
- **prompt 的判讀規則**：`EXTRACTION_GUIDE.md` 的每一條都對應一次真實的誤判。
  改它之前先讀那份文件，尤其是形近字那一節——
  曾有 11 份報告的抽取各自用同一個錯誤判準得到同一個錯字，
  而且都在 `issues` 裡寫下「已放大 8–18 倍確認」。**放大倍率再高，判準錯了還是錯的。**
